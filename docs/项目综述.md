# 项目综述（健身房/私教运营管理系统）

本文档总结了项目的基本功能、模块划分、代码结构、核心业务流程，以及运行/集成要点，帮助新成员快速上手。

## 1. 项目目标与领域
- 面向私教/健身房的运营管理：门店（Gym）、教练（Coach）、学员（User）、订单（Order）、排课（Schedule）。
- 财务（Accounting/Salary/Reimbursement）、数据统计（Statistics/Reports）、素材（Documents/Photos）、体测数据（BodyData）、任务/跟进（Task/Followup）等辅助模块。

## 2. 技术栈
- 后端：Laravel（JWT 认证、Spatie Permission 权限、Redis 缓存、事件/监听器、队列 Jobs）
- 前端：React + Material UI（resources/js，SPA 懒加载路由）
- 数据库：MySQL（迁移完整）
- 缓存：Redis（验证码、最新排课、月热力图、动作缓存等）
- 外部集成：
  - 微信小程序 openid 登录
  - 阿里云/云之讯短信
  - 大众点评（门店流量/评论抓取、券码核销）
  - 七牛上传（前端上传组件）

## 3. 运行与环境
- 环境依赖：PHP 7.3、MySQL 5.7、Composer、Yarn
- 初始化（详见 Readme.md）：
  1) composer install
  2) yarn install
  3) cp .env.example .env 并配置 DB_*
  4) php artisan migrate
  5) php artisan key:generate
  6) php artisan jwt:secret
  7) php artisan config:cache
  8) 前端构建：yarn watch
  9) 启动后端：php artisan serve

## 4. 后端架构与模块

### 4.1 核心实体与关系（app/*.php）
- Organization（组织）
  - hasMany Gyms（门店）
- Gym（门店）
  - hasMany Coaches；belongsTo Account
  - setting 时段/分享封面/点评绑定；timezone；点评抓取（DianpingJob）
  - 试课学员 Redis 管理：addTrialCustomer/getTrialCustomers
  - 汇总：getGymOrderBalance（余额/过期/未完成统计）
  - 最近完成排课缓存（Redis）：getGymLatestSchedules/setGymLatestSchedules
- User（用户/学员）
  - hasOne Coach；JWTSubject；HasRoles（Spatie）
  - 课程余额：getCourseBalance；首次订单：getFirstOrder
  - 热力图：getHotMap / schedulesToHotmap / getUserIdToHotmap
  - 最近排课/体测缓存（Redis）：getLatestScheduleCache / getLatestMeasureDate
  - 验证码：refreshVCode/verifyVCode
  - 用户分层：isNew/isRecent（报表使用）
- Coach（教练）
  - belongsTo Gym/User；is_gym_manager（角色映射）
- Order（订单）
  - belongsTo Gym/User(Customer)/Coach
  - 过期/完成度：hasExpired/getFinishedCount/getFinishedDate
  - 会计流水联动：getAccountingMessage/updateAccounting/deleteAccounting
  - 刷新预约数：refreshBooked
- Schedule（排课）
  - 重要字段：date、start/end（15 分钟粒度槽位，0..96），order_id（0=体验课）、status（1=未完成，2=完成）
  - 行为：冲突检查、followup 联动、完成/取消影响订单与点数、缓存更新
- Accounting（流水）：category/amount/detail/op/gym_id/order_id
- Reimbursement（报销）：op、approvedBy、coach/gym 关联
- SalarySetting/SalaryReceipt（薪资）：固定/比例/阶梯配置；toSalaryReceipt 转换
- Statistics（统计，简易）
- Homework/WorkoutAction/PlanTemplate：训练相关；WorkoutAction 带 Redis 全量缓存/默认值
- Documents（门店文档）
- Followup/Task/Talk/CoachWeeklyReport/CoachTrain：跟进/任务/消息/周报/培训
- Account/Billing：账户与点数账单（排课消耗、取消返还）

### 4.2 事件/监听器与队列
- 事件（app/Events）
  - OrderEvent：订单创建/退款 → 会计流水
  - ScheduleCreateEvent：新建排课 → 触发体测测量等
  - PayReimbursementEvent、PaySalaryEvent、BonusEvent 等
- 监听器（app/Listeners）
  - OrderAccountingAction：生成 Accounting 记录（收入/退款）
  - SalarySettingAddAction、SalaryPaymentAccountingAction、BodyDataMeasureAction 等
- 队列：DianpingJob 抓取点评数据（支持批量延时）

### 4.3 认证与权限
- JWT：AuthController 提供 login/register/me/logout/refresh/reset；支持短信验证码、微信 openid/bind
- 权限：Spatie Permission（示例角色："gym manager"）

## 5. 主要业务流程

### 5.1 订单创建（app/Http/Controllers/OrderController@store）
- 若 phone 不存在则创建用户（email=phone，默认密码），支持生日
- 创建订单：price、course_amount、duration、images、source、len（默认 4=1 小时）
- 计算 expiry=now+duration 月；关联 gym/coach/customer；保存
- 刷新客户订单索引；派发 OrderEvent → 生成会计流水

### 5.2 排课（app/Http/Controllers/ScheduleController）
- preSchedule：查找可用订单（status=1 且 booked_amount<course_amount 按到期早排序）
- store：
  - 体验课：指定 trial 或“该门店从未有订单的新客” → order_id=0
  - 正式课：绑定可用订单，end = start + len - 1；支持 Redis 暂存 detail；冲突校验 → 保存
  - 首次排课刷新订单 expiry（按排课日期+duration）
  - 订单 booked_amount++；联动 followup、触发 ScheduleCreateEvent；更新学员最新排课与体测缓存；Billing::consume 消耗 1 点
- update：更新 conclusion/detail（并保存默认动作值）、变更 order/coach；刷新关联订单 booked_amount
- destroy：解绑 followup、缓存 detail、删除 schedule；若绑定订单则 booked_amount--；更新门店最新排课缓存；Billing::cancel 返还 1 点
- complete：status=2；更新门店最新排课；触发跟进与 BonusEvent（达到门店设置阈值 bonus 时）

### 5.3 财务
- AccountingController：按时间范围查询门店流水；新增流水时带 created_by/gym_id
- OrderAccountingAction：监听订单事件生成“订单收入/退款支出”
- Billing（点数）：完成排课 -1，取消 +1；getAllBilling 汇总账户点数（考虑过期）
- Reimbursement/SalaryReceipt/SalarySetting 控制器：报销与薪资（路由已注册）

### 5.4 报表与分析（app/Http/Controllers/GymController & ScheduleController）
- getSummary：课程数、活跃用户、订单数/金额、新增用户、体验课数（需结合门店时区）
- 图表：
  - monthCourseByCustomerType：月上课次数（all/new/recent）
  - monthSaleByType：月销售额（all/new/recent）
  - monthActiveByType：月活跃人数（all/new/recent）
- workload：按 15 分钟粒度统计工作负载字符串（每天一串数字）

### 5.5 素材/体测/训练
- DocumentsController：门店文档 CRUD
- BodyData：体测数据卡片/图表、最近一次测量日期缓存
- WorkoutAction：动作全量缓存、按客户默认值

## 10. 关键设计与约定
- 时间槽与时长：Schedule.start/end 以 15 分钟为单位；Order.len 默认 4（1 小时）。创建排课时 `end = start + len - 1`。
- 体验课：order_id=0；试课学员使用 Redis（最近 30 天）并在客户名后以 🚀 标记（在部分接口返回中）。
- 流水来源：订单创建/退款通过事件生成 Accounting；订单属性变更尝试同步旧流水（Order::updateAccounting）。
- 缓存：
  - 学员最近排课（User::LATEST_SCHEDULE_PREFIX）
  - 门店所有学员最近排课快照（Gym::GYM_LATEST_SCHEDULE_PREFIX）
  - 学员最近体测日期（User::LATEST_MEASURE_PREFIX）
  - 月度热力图（User::MONTH_HOT_PREFIX）
  - 训练动作全量/默认值（WorkoutAction::ALL_ACTIONS_KEY）
- 报表分层：new/recent 依据用户 created_at 相对当前月或近 6 个月定义。

## 12. 开发者上手建议
- 从 routes/api.php 入手，结合 Gym/Order/Schedule 控制器跑通核心流程。
- 配置 Redis，启用验证码/最新排课/动作默认值等缓存逻辑。
- 若启用点评对接，配置 services.dianping 并在门店更新时触发历史数据抓取。
- 前端：确认 webpack 路径别名（-views、-utils）与懒加载正常。

## 13. 典型用例
- 教练登录（账号/短信验证码）→ 选择门店 → Dashboard 日历 → 预排/排课 → 完成排课（自动扣点/统计更新）。
- 前台录入订单 → 跟踪学员余额/过期/完成度 → 报表查看（月销量/活跃/新客） → 财务（流水/报销/薪资）。
- 体验课：扫码/链接访问 trial 课详情（无需登录）。
